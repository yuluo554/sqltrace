## 二、每里程碑收尾固定动作

1. 跑该里程碑 DoD 验证（含 golden / 基准）；
2. 布局门复跑绿；
3. plan/00 · 05 · 06 状态回写（副本一致）；
4. 写 `plan/HANDOFF-M<k>.md`（七节，M0 豁免）；
5. commit（有远端后 push 等 CI 绿）。

## 三、发布序列（M6 预演）

脱敏扫描 → 干净环境验证（真下载 + 解包 + 新 venv + 逐条敲 README）→ tag 前写好 `plan/RELEASE-M6.md` 两栏（§一 tag 前事实 / §二 tag 后追加；tag 树内不自指写哈希）→ annotated tag → `gh release create` 附产物 → tag 后只允许非交付面提交（POST_TAG_SCOPE + DELIVERABLE_UNCHANGED 两判据）。

> **v0.1.1 复用同一序列**，留档在 `plan/RELEASE-M6.1.md`（v0.1.0 的 `RELEASE-M6.md` 冻结不改）。

## 三之二、CI 镜像（D6 钉版本，v0.1.1 起）

三个 job 的 `runs-on` 一律钉 **`ubuntu-24.04`**（不再用 `ubuntu-latest`）。理由：`ubuntu-latest` 自
2026-10-19 起迁移 Ubuntu 26，跟随会让"三 job 全绿"的结论静默失效；钉版本把迁移变成有意识的决定。
2026-10-23 实跑镜像 = `ubuntu-24.04`（通过 `actions/runs/<id>/jobs` 的 `labels` 字段核对）。

- CI 实跑：**已关闭**。`.github/workflows/ci.yml` 首推 run `39466283266`（`ci` / `main` / push）三 job 全绿——布局门 4s、全量测试 + 五条 golden 13s、3.8 语法兼容 15s（ubuntu-latest / Linux）。**v0.1.1**：run `39901086436` 三 job 全绿（布局门 / 全量测试 + 五条 golden（3.12） / 最低支持版本 3.9 真装真跑，均 `ubuntu-24.04`，annotations 0），见 `plan/RELEASE-M6.1.md` §二。
- **本机无 Python 3.9**（只有 3.8.8 与 3.12.10）：`requires-python >=3.9` 由 CI 的 `py39-min` 腿真装真跑验证（`python 3.9.25 / sqlglot 30.24.0`、129 passed），不是本机实跑。
- 跨平台字节级一致：Windows 本机双跑与 **Linux CI**（`pytest` 内含双跑字节比对用例）均已验；**macOS 未验**（CI 无 macOS runner）。`git ls-tree`/`git show` 的路径形态差异仍是该项主要不确定点（实现已用 `--show-prefix` + `-z` + 统一 `/` 归一处理）。v0.1.1 起 Windows 输出经 `reconfigure(newline="\n")` 强制 LF，由 `tests/test_output_stream.py` 的真实子进程用例守着。
- sqlglot 版本升级行为漂移（pyproject 钉区间，升级必须重跑五条 golden）。
