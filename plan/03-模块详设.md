# 03 · 模块详设 — SQLTrace（M1–M5 实现级设计）

> 输入/输出/验收以 `plan/01` §二为准，本文写实现级设计、失败路径与接口签名。口径一律引用 `data/README.md` §四。

## M1 loader（语料装载 + schema 推导）

- 接口：`load_corpus(root: Path, schema_file: Path | None) -> Corpus`。
- 遍历：`Path.rglob("*.sql")` 后按相对路径排序；`.gitignore` 解析自研最小实现（嵌套 + 取反 + 跳过 `.git/`），被忽略文件进 `corpus.ignored[]` 带原因。
- 方言判定：文件扩展/目录约定 → 无法判定默认 `postgres` 并记 `dialect_defaulted`（口径 §4.5）。
- schema 推导：DDL `CREATE TABLE` 直接产出；CTAS / `CREATE VIEW ... AS SELECT` 正向传播（类型未知标 unknown，不编造）；语句间依赖拓扑排序（同层按 文件路径+语句序号），环报 `cycle_detected`。
- 失败路径：单文件超 2000 语句 → 中止该文件报诊断（§4.7）。

## M2 core（确定性列血缘内核）

- 接口：`build_edges(corpus: Corpus) -> tuple[list[Edge], list[Diag]]`。
- 流程：对每条语句取 sqlglot AST → 自研 scope walker：绑定 CTE/子查询别名 → 逐 SELECT 输出列回溯来源节点 → 按 §4.1 判定顺序分型（AST 确定不了 → unknown + reason code，先于 value/control）。
- 关键构造：
  - 窗口：值参数 → `value`；`PARTITION BY`/`ORDER BY` → `control`（**修正 sqlglot 同层无 kind 的实测错误**）。
  - 聚合：参数走 `value`，`aggregation` 字段记函数名。
  - CASE：THEN/ELSE → `value`；WHEN 谓词 → `control`。
  - JOIN：`join_path` 记连接链；WHERE/ON/USING/HAVING/QUALIFY → `control`。
- 元数据：每条边带 `expr`（表达式文本）、`statement_id`、`aggregation`、`window`、`join_path`。
- 验收：标注语料 `value` 精确率 100%、召回 ≥85%，未召回部分必须落 unknown（§4.3）。

## M3 fallback（降级策略引擎）

- 形态：`src/sqltrace/fallback.py` 四个出口——每档构造一个 handler，产出"展开边"或"诊断 + reason code"（枚举 §4.2，封闭）。
- 策略档与 reason code 一一对应 `plan/01` §二模块③表 + §4.2 现表（**14 档**，每档都有常驻触发用例）：

| 构造 | 处置 | 码 |
| --- | --- | --- |
| `SELECT *` + schema 已知 | 展开为具体列（正常路径，留 info 诊断） | `wildcard_expanded` |
| `SELECT *` + schema 未知 | `unknown` 边，不猜列名 | `unknown_wildcard`（边+诊断） |
| 列无法回溯到基表 | `unknown` 边 | `unknown_type`（边+诊断） |
| `UNION` 别名不一致 | 按位置合并 | `positional_union` |
| 列清单 / 显式列名与来源列数不符（含 `MERGE ... INSERT`） | 不猜位置，不产边 | `arity_mismatch` |
| `MERGE` 分支无列级边（DELETE / 无列清单 INSERT / 形态不支持） | 跳该分支 | `skipped_merge_branch` |
| `EXEC` / `EXECUTE IMMEDIATE` | 停止解析该块 | `UNSUPPORTED_DYNAMIC_SQL` |
| 解析失败 / 保护性上限中止 | 跳过该语句 | `PARSE_ERROR` |
| CTE/子查询深度 >16 或自引用 | 停止展开 | `recursion_limit` |
| 表依赖成环 | 环内语句按文件序追加 | `cycle_detected` |
| 目录判不出方言 | 回落 postgres | `dialect_defaulted`（文件级） |
| 写语句全常量、无来源列 | 边集为空是确定结果 | `no_source_columns` |
| 外部 `--schema` 覆盖同名表 | 采用外部定义 | `schema_overridden`（文件级） |
| 存储过程 / 函数体 | 整条跳过（D11） | `unsupported_stored_procedure` |

- **MERGE 是唯一由 fallback 直接产边的路径**（`resolve_merge`）：`UPDATE SET` → value 边（按 `t.col = s.col` 左值定位目标列）、`INSERT (c1,c2) VALUES (...)` → 按列清单位置映射、`ON` / `WHEN` 条件 → control 边并带 `join_path`；目标表自引用不入上游（不产 self-loop 假边）。核心里 `_target_of` 认不出 `Merge`，由 `build_edges` 显式路由。
- **零静默机械门**（`zero_silence_violations`）：`corpus.write_ids` 由 `build_edges` 收集（`INSERT` / `CREATE TABLE|VIEW ... AS` / `MERGE`，纯 DDL 与纯 SELECT 不在内）。写语句既无边也无**语句级**诊断 = FAIL；CLI 打印违规并以退出码 `4` 退出（§4.4），JSON 里落在 `zero_silence` 块。
- **边↔诊断双向对账**：`reconcile_unknown_edges` 保证每条 unknown 边有同 `(file, statement_index, reason_code)` 诊断；`diagnose_missing_edges` 反向保证 `unknown_wildcard`/`unknown_type` 的诊断必有对应边。
- **封闭枚举守卫**（`assert_reason_codes`）：出现枚举外的码即缺陷，同样退 `4`。

## M4 census（写入者普查）

- 接口：`census(corpus, edges=None) -> CensusReport`（writers/readers/orphan/multi_writer/write_only 五节，排序 §4.6）。口径单点见 `data/README.md` §4.8。
- **台账来源**（M4 实现落点）：`build_edges` 额外填写 `corpus.write_targets`（`statement_id -> 写目标表`）与 `corpus.reads`（`statement_id -> 读到的表`）。
  - 写者取自 `write_targets`（与 `write_ids` 同源，`INSERT` / `CREATE TABLE|VIEW ... AS` / `MERGE`），**不从边集反推**：全常量写语句边集为空（`no_source_columns`）却仍是写者。
  - 读者取自 `reads`（语句 AST 的 `Table` 节点，剔除 CTE 名与自身写目标）；**不从边集反推**：纯 `SELECT` 不产边但是读者，`unknown` 边 `source_table=None` 也不该被算成一张表。
  - 纯 DDL（无 `AS SELECT` 的 `CREATE TABLE`）既不是写者也不是读者。
- 判定：多写 = **写同一张表**（`len(writers[t]) >= 2`），不猜语义冲突；不输出风险分。
- 自检：`edges_missing_writer[]`——每条边的 `target_table` 必须登记过写者，非空即内部不一致（退出码 `4`）。
- 门复用：`census` 与 `lineage` 跑**同一份**边集与同一个零静默门（§4.2 规则 4），不各判一套。
- 输出：Markdown（可直接贴 PR）+ `--json`；`docs/census-sample.md` 是 `census data/corpus --md` 的真实输出（常驻测试逐字节比对）。

## M5 diffgate（diff 闸门 + impact + 输出）

> 口径单点 = `data/README.md` **§4.9**（规则 1–9）+ **§4.4**（退出码）。本节是设计回写：实现以 §4.9 为准。

- **接口**：`diffgate.diff_edges(base_edges, current_edges)` / `diff_exit_code(changes)` / `impact(corpus, edges, target)` / `run_golden(root, dialect=None)` / `load_base(root, base, dialect)` / `gate_check(...)`；`cli` 只做参数解析与输出。
- `diff --base <git-ref|dir>`：git 模式 `git ls-tree -r -z` 列文件 + `git show <ref>:<path>` 取内容（**只读**，不切工作区），双目录模式直读两目录；**两种模式喂同一个内核** `loader._assemble_corpus`（目录模式 `load_corpus`、git 模式 `load_corpus_from_texts`）。
  - `rev-parse --show-prefix` 带尾斜杠，拼 pathspec 前必须 `rstrip("/")`（否则 `git show` 退 128）。
  - 文件 sha 一律取**解码文本**的 sha（`_sha256_text`）：目录模式 `read_text` 走通用换行（CRLF→LF），若哈希原始字节则两模式对同一棵树给出不同 sha（M5 实测缺陷）。
- 边级 diff：分组键 `(target_table, target_column, kind)`；`ADDED` / `REMOVED` / `CHANGED`（CHANGED = 同键的**来源集合**变化）；`kind` 变化 = 旧键 REMOVED + 新键 ADDED。排序 §4.6。
- 退出码 §4.4：`0` 无变化 / `1` 有 `REMOVED`（**优先**）/ `2` 仅 `ADDED`·`CHANGED` / `3` 使用错误（目录不存在 / ref 不存在 / git 不可用 / 目标表不在图）/ `4` 门失败。**`1`/`2` 是 diff 专属**，`lineage`/`census`/`impact` 成功恒 `0`。
- `impact <table>.<column>`：上游来源（反向闭包）+ 下游消费者（正向闭包）+ `final_consumers` + `intermediate_tables`（**穿透层数的机械判据**）+ `reading_statements`（**取 `corpus.reads`**，K13：纯 `SELECT` 不产边但是消费者）。目标表不在血缘图 → 退 `3`。
- `golden <dir>`：遍历含 `expected.json` 的子目录，逐条跑 `lineage`/`census`/`impact`/`diff` 四类子检查 + 零静默门；**期望 JSON 由口径人工推导**（`plan/04 §二`），只含 `target`/`source`/`kind`（+ census/diff/impact 的集合与计数），不含实现风味字段；顶层键只认四类且至少一个（拼错必红）。
- 门复用（§4.9 规则 8）：`diff` 的**基线与当前**各跑一次 `gate_check`（= `zero_silence_violations` + `assert_reason_codes`），`golden` 的每份语料跑同一次；门红 → `4`，不掩盖成 `1`/`2`。
- 输出：JSON（稳定排序、键序固定）+ Markdown 评论块 + Mermaid **仅作附加块**。
- 确定性：`dumps_json` 单一出口；走 `sys.stdout.write`（**不是 `print`**——`print` 会再加一个换行，破坏 §4.6 的单 `\n` 约定）；路径统一 `/`，绝对路径只在计数里出现（`ref` 记 `null`）。

## 失败路径总表

| 失败 | 处置 | 码 |
| --- | --- | --- |
| 语句解析失败 | 定位行列、跳过**该语句**、不产边 | `PARSE_ERROR` |
| 存储过程 / 函数体含 DML | 整条跳过（首期不做体内血缘，D11） | `unsupported_stored_procedure` |
| `MERGE` 分支无列级边 | 跳该分支、留痕 | `skipped_merge_branch` |
| 写语句全常量、无来源列 | 边集为空（确定结果），留痕 | `no_source_columns` |
| 目录不存在 / base ref 不存在 / git 不可用 / 参数非法 | 退出码 3 | — |
| `impact` 目标表不在血缘图 / 目标非 `<table>.<column>` | 退出码 3（防打错字得空结果） | — |
| golden 期望不符 / 门红 | 退出码 4（期望侧是断言，不是快照） | — |
| golden 目录下没有 `expected.json` | 退出码 3（防空跑全绿） | — |
| CTE 层数 > 16 / 语句数 > 2000 / 节点数 > 200000 | 保护性中止 + 诊断 | §4.7 |
| 写语句既无边也无语句级诊断 | 零静默门 FAIL，退出码 4 | — |
| 内部断言失败 | 退出码 4（出现即缺陷） | — |
