# 03 · 模块详设 — SQLTrace（M1–M5 实现级设计）

> 输入/输出/验收以 `plan/01` §二为准，本文写实现级设计、失败路径与接口签名。口径一律引用 `data/README.md` §四。

## M1 loader（语料装载 + schema 推导）

- 接口：`load_corpus(root: Path, schema_file: Path | None) -> Corpus`。
- 遍历：`Path.rglob("*.sql")` 后按相对路径排序；`.gitignore` 解析自研最小实现（嵌套 + 取反 + 跳过 `.git/`），被忽略文件进 `corpus.ignored[]` 带原因。
- 方言判定：文件扩展/目录约定 → 无法判定默认 `postgres` 并记 `dialect_defaulted`（口径 §4.5）。
- schema 推导：DDL `CREATE TABLE` 直接产出；CTAS / `CREATE VIEW ... AS SELECT` 正向传播（类型未知标 unknown，不编造）；语句间依赖拓扑排序（同层按 文件路径+语句序号），环报 `cycle_detected`。
- 失败路径：单文件超 2000 语句 → 中止该文件报诊断（§4.7）。

## M2 core（确定性列血缘内核）

- 接口：`build_edges(corpus: Corpus) -> tuple[list[Edge], list[Diag]]`。
- 流程：对每条语句取 sqlglot AST → 自研 scope walker：绑定 CTE/子查询别名 → 逐 SELECT 输出列回溯来源节点 → 按 §4.1 判定顺序分型（AST 确定不了 → unknown + reason code，先于 value/control）。
- 关键构造：
  - 窗口：值参数 → `value`；`PARTITION BY`/`ORDER BY` → `control`（**修正 sqlglot 同层无 kind 的实测错误**）。
  - 聚合：参数走 `value`，`aggregation` 字段记函数名。
  - CASE：THEN/ELSE → `value`；WHEN 谓词 → `control`。
  - JOIN：`join_path` 记连接链；WHERE/ON/USING/HAVING/QUALIFY → `control`。
- 元数据：每条边带 `expr`（表达式文本）、`statement_id`、`aggregation`、`window`、`join_path`。
- 验收：标注语料 `value` 精确率 100%、召回 ≥85%，未召回部分必须落 unknown（§4.3）。

## M3 fallback（降级策略引擎）

- 形态：core 的钩子表——每档构造一个 handler，返回"展开边"或"unknown 边 + reason code"（枚举 §4.2，封闭）。
- 策略档与 reason code 一一对应 `plan/01` §二模块③表（`unknown_wildcard` / `positional_union` / `arity_mismatch` / `skipped_merge_branch` / `UNSUPPORTED_DYNAMIC_SQL` / `PARSE_ERROR` / `recursion_limit` / `cycle_detected` / `unknown_type`）。
- 零静默机械门：常驻测试断言 `grep -c unknown` == 诊断未解析计数；"解析了但无边也无诊断"的语句为 FAIL。

## M4 census（写入者普查）

- 接口：`census(edges, statements) -> CensusReport`（writers/readers/orphan/multi_writer/write_only 五节，排序 §4.6）。
- 判定：多写 = **写同一张表**（≥2 写入者），不猜语义冲突；不输出风险分。
- 输出：Markdown（可直接贴 PR）+ `--json`。

## M5 diffgate（diff 闸门 + impact + 输出）

- `diff --base <git-ref|dir>`：git 模式 `git show <ref>:<path>` 取基线语料（只读），双目录模式直读两目录，**两种模式喂同一内核**。
- 边级 diff：ADDED / REMOVED / CHANGED（同 `(target, column, kind)` 的来源集合变化）；退出码 §4.4（0/1/2/3，4=内部断言失败）。
- `impact <table>.<column>`：上游来源 + 下游消费者，穿透中间表（golden g5 验两层）。
- 输出：JSON（稳定排序、键序固定）+ Markdown 评论块 + Mermaid 仅作附加块。
- 确定性：同输入两次运行 JSON 字节级一致（`\n`、UTF-8 无 BOM、`ensure_ascii=False`、`indent=2`）。

## 失败路径总表

| 失败 | 处置 | 码 |
| --- | --- | --- |
| 语句解析失败 | 定位行列、跳过**该语句**、不产边 | `PARSE_ERROR` |
| 目录不存在 / base ref 不存在 / 参数非法 | 退出码 3 | — |
| CTE 层数 > 16 / 语句数 > 2000 / 节点数 > 200000 | 保护性中止 + 诊断 | §4.7 |
| 内部断言失败 | 退出码 4（出现即缺陷） | — |
