# 02 · 架构与技术选型 — SQLTrace

> 口径引用纪律：三类边定义 / reason code 枚举 / 退出码 / 方言列表 / 排序规则**只在 `data/README.md` §四定义一次**，本文只引用，不复制定义。

## 一、分层

```
┌────────────────────────────────────────────────┐
│ cli.py        唯一入口（argparse 命令树）        │  ← 单一入口纪律：只由 sqltrace 暴露
├────────────────────────────────────────────────┤
│ loader.py     M1 语料装载 + schema 推导          │
│ core.py       M2 确定性列血缘内核（scope walker） │
│ fallback.py   M3 降级策略引擎（reason code）      │
│ census.py     M4 写入者普查 / 冲突检测            │
│ diffgate.py   M5 lineage diff + impact + 输出    │
├────────────────────────────────────────────────┤
│ model.py      共享数据结构（Edge/Statement/Diag） │
│ constants.py  引用 data/README.md §四的数值常量   │
│ output.py     稳定排序 + JSON/Markdown 序列化     │
└────────────────────────────────────────────────┘
```

- **依赖方向**：cli → 各模块 → model/constants/output；模块之间不互相 import（census 消费 M2/M3 的边集合由 cli 传入）。
- **确定性纪律落点**：AST 只读不改写；不调用 sqlglot 的 `lineage()`/`qualify()` 作为判定路径；边去重键 = 全字段元组；所有输出经 `output.py` 单一出口排序（键 = `(target_table, target_column, kind, source_table, source_column, expr)`，Unicode 码点升序）。
- **M1–M5 与模块的对应**：loader=M1、core=M2、fallback=M3、census=M4、diffgate=M5（impact 在 diffgate）。

## 二、技术选型（决策引用）

| 项 | 选择 | 依据 |
| --- | --- | --- |
| 解析器 | sqlglot 30.23.0（**钉死版本区间 `>=30.20,<31`**），只当解析器用 | D5：lineage() 实测缺陷清单见 `data/README.md` §一 |
| scope 解析 | 自研 scope walker（sqlglot 只产 AST） | 同上；sqlglot lineage 输出不带 kind、窗口分区键当值 |
| 运行时 | Python ≥3.9（**v0.1.1 起**；D3 修正：`sqlglot>=30.20` 自身要求 ≥3.9，旧的 `>=3.8` 承诺装不上），标准库 argparse/json/hashlib | 纯本地 CLI，无服务端 |
| 外部 schema | `--schema <ddl.sql>` 覆盖同名推导表，诊断记 `schema_overridden` | plan/01 模块① |
| diff 基线 | git 模式 `git show <ref>:<path>`（只读、不切工作区）+ 双目录模式 | plan/01 模块⑤ |
| 测试 | pytest + golden 回归 + 双跑逐字节 | M5 DoD |

## 三、构建与打包

- `pyproject.toml`（PEP 621，setuptools，src 布局），console script `sqltrace = sqltrace.cli:main`。
- sdist/wheel 构建于 `git archive <tag>` 导出的干净目录（附件与 tag 树同源）。
- `MANIFEST.in` 白名单覆盖 `data/golden/`、`data/labels/`、`data/README.md`（源码包自足）。
- 零网络验证：静态扫描（无 requests/urllib/http.client/socket 导入）+ 常驻测试锁死。
